# Parity audit gaps (partial audit: composer/media/settings areas only)
# 10 areas unaudited: profiles, room-settings, stickers, calls, verification, core-spine, polls-threads, roomlist-ui, timeline-ui, search-newchat

## Critical/major (unfixed — fixer hit session limit)

- [critical] android/app/src/main/kotlin/com/riiiiiiiley/discourse/features/timeline/ComposerView.kt: Mention autocomplete is entirely missing. Swift ComposerView tracks a trailing '@token' (updateMentionQuery), shows up to 6 member suggestions (avatar + name + mxid, folded-name matching, excluding self), inserts the full '@user:server' token, records ChosenMention entries, and passes resolvedMentions() to sendComposed so intentional mentions (MSC3952) and matrix.to anchors are emitted. Kotlin's send() calls viewModel.sendComposed(message) with no mentions; the VM already supports a mentions parameter (TimelineViewModel.sendComposed/sendText/mentionHtml) but the composer never builds one, so users cannot mention anyone from the Android composer.
- [critical] android/app/src/main/kotlin/com/riiiiiiiley/discourse/features/timeline/ComposerView.kt: Custom-emote/unicode ':token:' autocomplete is missing. Swift updateEmoteQuery() suggests custom emotes (prefix-then-contains over CustomEmojiStore.sortedEmoticons) plus unicode emoji from EmojiShortcodes.matches (max 8 rows), with a suggestion popover and insertion logic. Kotlin EmojiPicker.kt ports EmojiShortcodes (entries/byShortcode/matches) but nothing in ComposerView.kt consumes it — typing ':pleadi' produces no suggestions.
- [critical] android/app/src/main/kotlin/com/riiiiiiiley/discourse/features/timeline/TimelineViewModel.kt: Custom emote ':shortcode:' tokens are never converted to <img> HTML at send time (comments at lines ~100 and ~804 say the conversion 'attaches when those stores land'). ComposerView.kt line ~347 inserts emote.token from the picker with a comment admitting it's interim — so picking a custom emoji from the Android picker sends literal ':shortcode:' text to the room, while iOS renders it as an inline image. The insert path exists but the feature is broken end-to-end.
- [critical] android/app/src/main/kotlin/com/riiiiiiiley/discourse/features/timeline/ComposerView.kt: Typing indicator display is absent. Swift shows a 'X is typing…' / 'X and Y are typing…' / 'Several people are typing…' glass tag above the bar (gated on prefs.showTypingIndicators, names resolved via membersById with mxid-localpart fallback). Kotlin TimelineViewModel exposes typingUsers (StateFlow) and the pref exists, but no UI anywhere in the timeline/composer renders it (grep for typingUsers outside the VM returns nothing).
- [major] android/app/src/main/kotlin/com/riiiiiiiley/discourse/features/timeline/ComposerView.kt: Voice-message hold gesture is missing: Swift iOS has hold-to-record (zero-distance drag), slide-left-to-cancel with threshold + trash tint + 'Slide to cancel' hint riding the finger, slide-up-to-lock with lock pill and progress fill, haptic ticks on lock/cancel edges, sub-0.5s tap shows a 'Hold to record, release to send' hint, release-to-send, and a VoiceOver accessibility action that toggles a locked recording. Kotlin is tap-to-start then a static RecordingStrip with cancel/send buttons — no hold, slide, lock, hints, or VoiceOver/TalkBack path.
- [major] android/app/src/main/kotlin/com/riiiiiiiley/discourse/features/timeline/ComposerView.kt: 'Share Location' fires immediately from the attach menu (onClick launches viewModel.shareCurrentLocation()). Swift always shows a confirmation dialog first ('Share your current location?' with Share/Cancel) before broadcasting location — a deliberate privacy gate that the Kotlin port drops.
- [major] android/app/src/main/kotlin/com/riiiiiiiley/discourse/features/timeline/ComposerView.kt: The 'Photo or Video' attach item launches filePicker with mime filter "image/*" (line ~237), which excludes videos despite the label. iOS's photosPicker matches .any(of: [.images, .videos]) and routes movie types through a video staging path. Videos are only reachable on Android via the generic 'File' (*/*) entry.
- [major] android/app/src/main/kotlin/com/riiiiiiiley/discourse/features/timeline/ComposerView.kt: Draft stash/restore around edits is missing. Swift stashes the in-progress draft when an edit begins (draft→edit transition only), restores it when the edit is cancelled or completes, and suppresses draft persistence while the edit occupies the field. Kotlin's edit-banner dismiss sets text = "" (line ~185), destroying whatever the user had typed before tapping Edit; the field text while editing also overwrites viewModel.draftText via onValueChange.
- [major] android/app/src/main/kotlin/com/riiiiiiiley/discourse/features/timeline/ComposerView.kt: AttachmentPreviewChip never renders the uploadFailed state. Swift draws a red stroke border, a white-on-red exclamation badge, and an accessibility label 'upload failed — will retry when you send'. Kotlin's TimelineViewModel does set uploadFailed = true on restaged failures (restageFailedUpload), but the chip only shows preview/loading/doc-icon, so a failed upload is indistinguishable from a healthy staged attachment (only the transient composer error hints at it).
- [major] android/app/src/main/kotlin/com/riiiiiiiley/discourse/features/timeline/ComposerView.kt: Closing-colon shortcode auto-replace is missing: on iOS, typing the final ':' of an exact unicode shortcode (':pleading_face:') swaps it in place for the emoji, with guards for word-start (so '10:30:' survives) and single-character growth (so pastes aren't rewritten). Kotlin's onValueChange only updates draft and typing notice; EmojiShortcodes.byShortcode is ported but unused for this.
- [major] android/app/src/main/kotlin/com/riiiiiiiley/discourse/features/timeline/ComposerView.kt: Expression panel is a fixed 280.dp inline block with a divider and explicit close button, not the iOS keyboard-replacement panel: no keyboard-height matching (expressionPanelHeight from last real keyboard height minus latched inset), no drag grabber to expand to ~75% of the window with two detents, no downward-fling-to-close, no synchronized keyboard/panel swap keeping the bar at constant lift, and the toggle icon never flips to a 'keyboard' glyph while the panel is up. The panel search-focus coexistence machinery (panelSearchActive / onSearchFocusChange) is also unwired — ComposerView passes no onSearchFocusChange to EmojiPickerView even though the parameter exists.
- [critical] /Users/riley/Developer/Discourse/android/app/src/main/kotlin/com/riiiiiiiley/discourse/features/settings/SettingsTab.kt: StickerMakerView is not ported and there is no 'Stickers' row in the Customization section (comment at line ~227 says it attaches 'once the StickerStore + MediaLoader ports land', but both core/StickerStore.kt and core/media/MediaLoader.kt already exist and SessionScope has a stickers store). iOS SettingsView.swift lines 595-601 + 691-969: pick image, name it, choose/create a pack (with existing-pack menu), add (crop/scale/upload, MSC2545), per-pack listing with per-row delete + long-press delete, error surface, and empty-state text. The entire sticker creation/management feature is absent on Android.
- [major] /Users/riley/Developer/Discourse/android/app/src/main/kotlin/com/riiiiiiiley/discourse/features/settings/SettingsTab.kt: LinkIconPickerSheet (line ~887) calls EmojiPickerView without customPacks or loader, so choosing a custom emote (mxc URL) as a social-link icon is impossible — only unicode emoji can be picked. iOS EmoteIconPicker (SettingsView.swift:484-529) passes scope.customEmoji.packs and scope.mediaLoader. Kotlin's EmojiPickerView already accepts customPacks/loader params and SessionScope.customEmoji exists (SessionScope.kt:44), so it just isn't threaded through.
- [major] /Users/riley/Developer/Discourse/android/app/src/main/kotlin/com/riiiiiiiley/discourse/features/settings/SettingsMedia.kt: NotificationSettingsScreen per-account rows omit the unread badge (commented out at line ~119 claiming AppState lacks per-account unread counts, but AppState.unreadCount(forUserId) exists at AppState.kt:82). iOS SettingsMedia.swift:50-53 shows UnreadBadge(count) next to each non-active account with unread > 0. The UnreadBadge composable itself is already ported (same file, line 136) but unused.
- [major] /Users/riley/Developer/Discourse/android/app/src/main/kotlin/com/riiiiiiiley/discourse/features/settings/SettingsTab.kt: SettingsRootScreen Accounts section (line ~256) omits the unread badge on non-active account rows for the same stale reason; iOS ProfileTabView (SettingsView.swift:629-633) shows UnreadBadge for each non-active account with unread > 0, so the Android user can't see pending activity on other signed-in accounts from Settings.
- [critical] android/app/src/main/kotlin/com/riiiiiiiley/discourse/features/timeline/media/InlineImageView.kt: FullScreenImageViewer decodes the full-resolution bytes with BitmapFactory.decodeByteArray(data, 0, data.size) with no subsampling and draws the result via Compose Image. A typical modern phone photo (12-48MP) produces a 50-200MB software bitmap, which either throws 'Canvas: trying to draw too large bitmap' (app crash) or returns null from decode, leaving an eternal spinner with no error state. The iOS original hands the file to QuickLook, which tiles/downsamples internally and handles arbitrary sizes. The decoder needs inSampleSize bounding (like MediaLoader.decodeThumbnail already does) or a subsampling viewer.
- [major] android/app/src/main/kotlin/com/riiiiiiiley/discourse/core/MediaProcessing.kt: sanitizedImage() fully re-encodes every outgoing image to PNG (alpha) or JPEG quality 90, discarding the original container format, the ICC color profile, and ALL metadata. The Swift original (MediaProcessing.swift:35-67) rewrites in the source's own format via CGImageDestination and nulls ONLY the GPS dictionary, keeping everything else (capture date, orientation tag, color profile). Consequences on Android: a lossless PNG screenshot without alpha is shipped as lossy JPEG; WebP/HEIC become JPEG/PNG so the sent mimetype no longer matches the picked filename's extension; Display-P3 photos color-shift.
- [major] android/app/src/main/kotlin/com/riiiiiiiley/discourse/core/MediaProcessing.kt: The animated-image passthrough only checks mimetype == "image/gif" (line 74). Swift checks CGImageSourceGetCount(source) > 1 (MediaProcessing.swift:45-48), which covers APNG and animated WebP as well. On Android an animated WebP or APNG gets flattened to a single re-encoded frame before sending.
- [major] android/app/src/main/kotlin/com/riiiiiiiley/discourse/features/timeline/media/InlineImageView.kt: No share/save/export path from the full-screen image viewer (and none from VideoPlayerDialog in VideoAttachmentView.kt). iOS QuickLook provides the system share sheet (save to Photos, share, markup), and macOS additionally supports drag-out via TimelineImageTransfer (that part is platform-specific, but the share/save capability itself is not). On the Android port there is no way at all to save received media to the device.
- [major] android/app/src/main/kotlin/com/riiiiiiiley/discourse/features/timeline/media/InlineImageView.kt: Animated GIFs/WebP open as a static first frame in FullScreenImageViewer (BitmapFactory.decodeByteArray only yields frame 0). iOS QuickLook plays the animation. Inline thumbnails are static on both platforms, so the viewer was the only place animation played — that behavior is absent on Android.

## Minor

- android/app/src/main/kotlin/com/riiiiiiiley/discourse/features/timeline/ComposerView.kt: Sending a sticker closes the expression panel (expressionPanel = null in both send and sendPackSticker). The iOS iOS-panel behavior deliberately keeps the panel up 'so stickers can be chained' (only macOS closes its popover).
- android/app/src/main/kotlin/com/riiiiiiiley/discourse/features/timeline/ComposerView.kt: send() does not trim the message: iOS sends text.trimmingCharacters(in: .whitespacesAndNewlines); Kotlin sends the raw text (only isBlank-gated), so leading/trailing whitespace and newlines go out verbatim.
- android/app/src/main/kotlin/com/riiiiiiiley/discourse/features/timeline/ComposerView.kt: Custom-emote insertion from the picker appends emote.token with no trailing space (text + emote.token), while iOS appends 'token + " "'; consecutive emotes or following text will fuse into one unparseable token.
- android/app/src/main/kotlin/com/riiiiiiiley/discourse/features/timeline/ComposerView.kt: Edit prefill uses previewText() for every message kind (image/video captions, poll question, 'Message deleted', etc.), whereas iOS only prefills when the edit target kind is .text — editing a non-text message on Android loads a lossy preview string into the field.
- android/app/src/main/kotlin/com/riiiiiiiley/discourse/features/timeline/ComposerView.kt: The inline emoji panel never refreshes custom-emoji packs on open; iOS runs .task { await customEmoji?.refreshIfStale() } when the picker appears (packs go stale as the user joins rooms). Kotlin CustomEmojiStore.refreshIfStale exists but is not called from the composer's panel path (the unused EmojiStickerPicker wrapper has a refreshCustomEmoji hook, but ComposerView builds its own panel without it).
- android/app/src/main/kotlin/com/riiiiiiiley/discourse/features/timeline/ComposerView.kt: No 'Recording interrupted' user feedback: iOS shows a transient hint capsule when the system stops the recorder (recorder.interrupted); Kotlin silently calls recorder.stop(cancelled = true) and the strip just disappears. Also no live waveform: VoiceRecorder.kt exposes levels (StateFlow) but RecordingStrip renders only the red dot + timer, missing iOS's WaveformBars(samples: recorder.levels.suffix(60)).
- android/app/src/main/kotlin/com/riiiiiiiley/discourse/features/timeline/ComposerView.kt: No drop target on the composer: iOS accepts drops of files and raw image data (ComposerDropItem dropDestination) and stages them as attachments; Android (tablet/desktop-window drag-and-drop via Modifier.dragAndDropTarget) has no equivalent, and there is no paste-image staging path either.
- android/app/src/main/kotlin/com/riiiiiiiley/discourse/features/timeline/EmojiPicker.kt: Search field does not disable autocorrect/suggestions (iOS sets .autocorrectionDisabled() because 'emoji shortcodes aren't dictionary words'); the Kotlin BasicTextField uses default KeyboardOptions so the IME may autocorrect shortcode queries. Grid cells also lack the iOS press/hover feedback (PressFeedbackStyle scale/opacity and hover highlight) — taps give no visual acknowledgment.
- android/app/src/main/kotlin/com/riiiiiiiley/discourse/features/timeline/EmojiPicker.kt: Scrolled-category highlight logic differs: Kotlin highlights the section of the first visible cell (firstVisibleItemIndex), while iOS highlights the section whose header most recently crossed a 90pt line with a keep-current fallback; the Android highlight flips one row earlier/later than iOS near section boundaries. Cosmetic drift, but the mechanism was explicitly tuned on iOS to avoid mid-scroll jumps.
- /Users/riley/Developer/Discourse/android/app/src/main/kotlin/com/riiiiiiiley/discourse/features/settings/SettingsTab.kt: Identity-card avatar (SettingsRootScreen line ~190) lacks the presence indicator dot; iOS ProfileTabView applies .presenceIndicator(userId: scope.userId, size: 15) (SettingsView.swift:553). - /Users/riley/Developer/Discourse/android/app/src/main/kotlin/com/riiiiiiiley/discourse/features/settings/SettingsAppearance.kt: The Theme segmented picker renders text-only labels; iOS shows an icon per mode (circle.lefthalf.filled / sun.max / moon via AppearanceMode.symbol, SettingsAppearance.swift:24 + Preferences.swift:229-235). - /Users/riley/Developer/Discourse/android/app/src/main/kotlin/com/riiiiiiiley/discourse/features/settings/SettingsTab.kt: Profile editor text fields (LabeledFieldRow for Name/Pronouns/Status, TimezoneRow) set no IME action; iOS marks these fields .submitLabel(.done) (SettingsView.swift:284, 305) so the keyboard shows Done and dismisses on submit. - android/app/src/main/kotlin/com/riiiiiiiley/discourse/core/media/VoiceRecorder.kt: Dead duplicate: this class is referenced nowhere — ComposerView.kt uses the divergent copy at features/timeline/VoiceRecorder.kt (which returns VoiceRecording from TimelineViewModel.kt and adds an isRecording re-entry guard and empty-data check the core copy lacks). - android/app/src/main/kotlin/com/riiiiiiiley/discourse/features/timeline/VoiceRecorder.kt: Metering uses MediaRecorder.maxAmplitude (peak since last read) mapped to dB, while iOS uses AVAudioRecorder.averagePower (RMS average, VoiceRecorder.swift:97). - android/app/src/main/kotlin/com/riiiiiiiley/discourse/features/timeline/VoiceRecorder.kt: No audio focus is requested while recording. iOS activates a .playAndRecord AVAudioSession (VoiceRecorder.swift:31-42), which silences other audio for the duration of the take; on Android any playing music keeps playing (and bleeds into the mic). - android/app/src/main/kotlin/com/riiiiiiiley/discourse/features/timeline/media/VoiceMessageView.kt: AudioPlaybackController.createPlayer writes decrypted audio to cacheDir as 'discourse-audio-<hash>' files that are never cleaned up (no analogue of MediaLoader's cap/trim). iOS plays E2EE audio purely from memory via AVAudioPlayer(data:). - android/app/src/main/kotlin/com/riiiiiiiley/discourse/features/timeline/media/InlineImageView.kt: FullScreenImageViewer pinch-zoom has no pan clamping (the image can be dragged fully off-screen at any zoom level) and no double-tap-to-zoom; QuickLook rubber-bands and supports double-tap. - android/app/src/main/kotlin/com/riiiiiiiley/discourse/features/timeline/media/VideoAttachmentView.kt: VideoPlayerDialog is a Dialog that does not hide the status/navigation bars, so playback is not truly fullscreen (iOS QuickLook is). - android/app/src/main/kotlin/com/riiiiiiiley/discourse/core/MediaProcessing.kt: sanitizedImage() decodes the full-resolution bitmap into memory with no sampling (BitmapFactory.decodeByteArray at line 73) before re-encoding — OOM risk for very large sources.
